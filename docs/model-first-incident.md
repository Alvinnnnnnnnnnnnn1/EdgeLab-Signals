## Implemented reliability changes

Missing final rows now return explicit `pendingFinalEvidence` identities from the existing grader. The supervisor does not cache unresolved grading as complete; the grading-version marker changes so an old zero-held checkpoint cannot suppress the first new assessment. Existing idempotent settlement, append-only corrections and outbox behavior are preserved.

The read-only Bet Log distinguishes Pending final evidence, Pending processing and Disputed, alongside existing won/lost/push/void results. Disputed means retained final evidence fails identity, chronology, source or settlement validation; it does not fabricate an outcome or rewrite an existing grade. CSV columns and chronological cumulative accounting remain unchanged.

An optional `recommendationExposure` configuration contains `enabled` and a nullable owner-approved policy. A policy must identify its approval, effective/expiry clocks, `maxPerFixture` and `maxPerPlayerFixture`. Enabling it without valid policy evidence blocks new issuance. It counts all immutable issues inside the same IMMEDIATE suggestion/outbox transaction; delivery/grade/failure/restart cannot release exposure. Eligible candidates are ranked using the unchanged score. Research observations remain independent. Newly governed issues freeze the policy identity/hash and limits. Permanent per-prop family suppression remains separate. No numeric production limit was chosen from this losing slate; the governor is disabled in existing configuration until the owner supplies explicit risk limits. Disabled behavior preserves legacy singles.
